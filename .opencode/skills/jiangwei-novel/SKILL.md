# 小說生成規範

本 skill 適用於整個專案。凡是分析 `ExtractedScripts/`、續寫小說章節、修訂既有小說或整理分支，都必須遵守以下規則。

本 skill 提及的 `ExtractedScripts/`、`chapters/`、`story-routes-and-branches.md` 及其他專案路徑，均相對於目前 workspace 根目錄。

若將相關工作委派給 subagent，必須在委派提示中要求每個 subagent 先載入 `jiangwei-novel` skill，再讀取或修改相關檔案。

凡生成、續寫、審閱或修訂章節中的直接對話與內心獨白，還必須先閱讀 workspace 根目錄的 `dialogue-speaker-guidelines.md`。該文件提供提示密度與版面範例；若其內容與本 skill 的來源驗證、說話者歸屬或零改動規則衝突，以本 skill 為準。

## 一、專案目標

將 `ExtractedScripts/` 內的遊戲劇本改寫為繁體中文長篇小說，整體採用：

- 三國演義式章回敘事
- 現代輕小說的閱讀節奏
- 原始遊戲文本的角色性格、幽默與世界觀
- 不改動原始角色台詞的忠實改寫方式

小說不是逐行貼上劇本，也不是重新創作另一個故事。工作核心是保留原劇情與對話，補足場景、動作、戰陣、情緒、時代背景和敘事銜接，讓遊戲腳本成為可獨立閱讀的小說。

## 二、資料來源與優先順序

### 1. 原始文本

- `ExtractedScripts/R_00.txt` 至 `R_58.txt`：章間劇情、人物互動、選項與尾聲。
- `ExtractedScripts/S_00.txt` 至 `S_57.txt`：戰場事件、單挑、戰中對話與勝敗條件。
- 原始文本是人物台詞、事件結果與角色關係的最高優先來源。
- 原始文本中附於台詞前的 `角色名：` 也是說話者歸屬的最高優先證據。解析時可將角色名與台詞內容分欄，但不得丟棄說話者欄位。
- `士兵01`、`步兵1`、`女子1` 等技術性標籤仍代表特定發話實體。小說可將其自然化為一名士卒、步兵或女子，但不得無證據改成具名角色。

### 2. 劇情分析

- `story-routes-and-branches.md`：用於確認共通線、陰平分流、亡國線、真結局線與尾聲版本。
- 分析文件只能協助理解流程，若與原始文本衝突，必須以原始文本為準。
- 分析文件中標為「推定」或「高度可信」的內容，不得擅自改寫成確定事實。

### 3. 既有小說

- `chapters/novel-chapter-01.md` 是文體、章節結構和改寫密度的基準範例。若其對話提示方式與本規範的說話者清晰度要求衝突，必須以本規範為準，並先修正第一章後再作為後續範例。
- 續寫時要延續既有稱謂、人物語氣、標點、敘事距離與 Markdown 格式。
- 若既有小說與原始台詞不一致，應修正小說，不得反過來修改原始文本。

## 三、章節來源判定

### 1. 不可只按檔名機械配對

一般情況下，小說一章可由同編號的 `R_n` 與 `S_n` 組成，再以 `R_(n+1)` 開頭確認前一戰結果和章節終點。例如第一章使用 `R_00 + S_00`，`R_01` 已轉入冀城，是下一章起點。

但這不是絕對規則：

- 某些 `R_*` 同時收錄戰前、戰後與其他陣營事件。
- 某些 `S_*` 的結果要到下一份 `R_*` 才明說。
- `R_32` 之後因陰平選擇分成 `S_32/S_33` 亡國線與 `R_34/S_34` 架空線。
- `R_58` 同檔含「孤臣之死」與「真正的終局」兩個不同入口。

每次寫新章前，必須先閱讀：

1. 預定使用的 `R_*` 全文。
2. 對應 `S_*` 全文。
3. 前一份文本的結尾。
4. 下一份 `R_*` 的開頭，確認本章戰果與下一章場景。
5. `story-routes-and-branches.md` 的相應路線段落。

### 2. 先定義章節起訖

開始寫作前，先在工作筆記中明確列出：

- 本章開始場景
- 本章結束場景
- 使用的來源檔案
- 採用的劇情路線
- 採用的選項
- 本章必須出現的事件
- 下一章銜接點

不要把下一章已開始的新地點、新任務或新衝突硬塞進本章。

## 四、路線與選項規則

### 1. 主路線

- `R_00` 至 `R_32` 原則上依共通線續寫。
- 到 `R_32` 時，除非使用者另有指定，預設採用「派遣軍隊去防守」，進入架空真結局線。
- 若使用者指定史實／亡國線，改採「不派遣軍隊防守」，不得混入防守陰平線的事件。
- 寫到 `R_58` 前，必須先確認進入的是「孤臣之死」還是「真正的終局」。

### 2. 一般選項

- 寫作前必須明確選定本章採用的選項版本。
- 優先選擇能延續主要人物、完整呈現重要事件、符合真結局線鋪陳的版本。
- 若兩個選項只改變難度或戰術，選擇較合理、較能形成完整小說場面的版本。
- 若選項涉及角色死亡、加入、感情或後日談，必須查閱後續文本，避免造成連續性錯誤。
- 不得把互斥選項後的兩組台詞合併為同一場景。
- 不得為了收錄所有文字，讓角色連續做出互相矛盾的決定。

### 3. 分支紀錄

每章末尾保留「改寫註記」，至少記錄：

```markdown
## 改寫註記

- 本章取材範圍：`ExtractedScripts/R_XX.txt` 與 `ExtractedScripts/S_XX.txt`。
- 主分支採用：`選項一`、`選項二`。
- 所有取用的角色台詞與角色內心獨白均保留原文。
- 台詞內容與說話者驗證：簡述逐字比對、角色歸屬、匿名處理及未決項結果。
- 未採用的互斥分支與省略的系統文字：簡述原因。
```

## 五、原始對話零改動與說話者歸屬規則

這是小說改寫的最高優先規則。

### 1. 必須逐字保留

凡是本章所採用路線中的以下文字，都必須保留：

- `角色名：台詞`
- `角色名：（內心獨白）`
- 單挑段落中省略角色名的台詞
- 戰中事件中可判定為人物說話的無名台詞

不得修改：

- 用字
- 語序
- 稱謂
- 語助詞
- 粗口
- 玩笑
- 數字
- 專有名詞
- 全形標點
- 引號種類
- 省略號數量
- 括號內容

例如原文內含 `「趙」`，小說中不得改成 `『趙』`。外層小說引號即使因此形成相鄰引號，也以保存原文為優先。

### 2. 唯一可正規化項目

匯出器為排版而插入的換行與多餘空白可以合併，使句子正常連續；除此之外不得潤飾台詞。

例如：

```text
原文：我軍的軍隊 根本沒有辦法和他們抗衡。
小說：我軍的軍隊根本沒有辦法和他們抗衡。
```

只可移除可確定是匯出斷行造成的空白，不可順便改字或修正文法。

### 3. 不得新增直接對話

- 不要替角色創作原文不存在的新台詞。
- 需要補充資訊時，使用旁白、動作、表情或間接引語。
- 不得用新台詞解釋戰術、歷史背景或角色心理。
- 原文未說出口的情緒，只能寫成敘述，不得擅自加上引號。

### 4. 對話呈現

- 小說正文使用全形直角引號 `「」` 包住說出口的台詞。
- 內心獨白沿用原文全形括號 `（）`，不另加引號。
- 每一段台詞獨立成段，以維持輕小說節奏。
- 可以在台詞前後加入說話者動作、神情和場景反應，但不可插入台詞句中。
- 台詞獨立成段不等於可以失去說話者提示；提示必須位於台詞之外，且不得改動台詞內容。

### 5. 台詞內容與說話者雙重不可變

每句採用台詞都必須同時通過兩項互相獨立的要求：

1. 台詞內容與來源逐字相同，只容許本節規定的匯出排版空白正規化。
2. 台詞必須歸屬於來源指定或經可靠證據判定的同一說話者。

只做到其中一項不算合格。台詞文字完全相同但放到錯誤人物身上，仍屬重大原文錯誤。驗證單位必須是不可拆分的三元組：

```text
來源記錄 ID＋原始說話者／安全匿名身分＋逐字台詞內容
```

### 6. 讀者可見的說話者錨點

- 每句直接對話及每句內心獨白，都必須讓未查閱來源檔的讀者以低負擔辨識發話者。
- 採風險點補提示，不要求機械式地在每句台詞前重複「某某說」。
- 對話開始、換場、分節或敘事視角切換後的第一句，必須重新建立說話者錨點。
- 三人以上的場景中，每次說話者改變時，必須在新說話者的第一句台詞前重新建立錨點。
- 同一人物連續說出數句來源台詞時，一個明確錨點可涵蓋整個連續區塊；一旦其他人物發話、插入其他人物動作、轉換視角、換場或分節，該錨點即告失效。
- 嚴格二人場景在雙方均已明確登場、輪替未中斷且沒有歧義時，可省略逐句提示；插入長篇旁白、內心獨白、第三人、久未發言者重新開口或可能誤接的動作後，必須重新錨定。
- 嚴格二人快速對話建立順序後，通常可省略二至四輪提示；這只是節奏參考，不是機械上限。既有章節若每句都使用模板式說話標記，應在不影響辨識的前提下刪減重複提示。
- 實際順序為 `A、A、B` 時，若第二句不顯然延續第一句，必須在第二句前加入延續錨點，避免讀者按 `A、B、A` 錯配。
- 場景第一句、久未發言者重新開口、內心主人切換及前文焦點人物並非下一句說話者時，應優先使用前置錨點。
- 後置錨點只可緊接在該句之後，且不得讓讀者讀完後續台詞才回頭修正歸屬。
- 當場有兩名以上可能對象時，不得只用「他」「她」「有人」「那人」「一道聲音」作為來源已具名台詞的唯一錨點。
- 來源已明確具名時，錨點原則上使用角色姓名、當場唯一的字號、唯一官職或不會與其他在場人物混淆的稱謂，不得降格寫成「有人」來規避歸屬驗證。
- 清晰度優先於避免重複人名，但提示應保持簡短，不重述台詞已表達的內容。
- 提示方式依序優先採用有情節作用的動作、神情或反應、簡短說話標記；不得為了避開「說道」而堆疊無意義小動作。

說話者隔離測試：將台詞與最近的有效敘事錨點單獨截出，在不查看來源、不依賴角色口癖、不計算多人場景對話輪次的情況下，仍應能回答是誰在說話。不能回答且又不屬於來源刻意匿名者，即為不合格。

### 7. 說話者判定證據

說話者判定依下列優先順序進行，低層級證據不得推翻高層級證據：

1. 同一來源記錄的明確 `角色名：` 標籤，包含具名角色與技術性匿名標籤。
2. 同一句在平行版本或同一事件重複段落中的明確標籤；必須先證明兩者確屬同一事件，不能只因文字相同就合併。
3. 原始事件結構，例如具名單挑雙方、施招、受擊、進退場、死亡、撤退及戰果。
4. 局部語義與應答關係，例如自報姓名、唯一稱謂、明確問答、施招者與受擊反應；單一線索若仍有多個可能人物，不足以定案。
5. 前後 `R_*`、`S_*`、下一章開頭、平行分支與角色在場狀態的交叉印證。
6. 排除式場景推理；宜與前述另一項獨立證據合用。

下列資訊不得單獨作為說話者證據：

- 一人一句交替。
- 台詞距離哪個人物最近。
- 「這句很像某人的個性」。
- 口癖、粗口、結巴或招牌語氣。
- 既有小說目前如何安排。
- 對遊戲演出的模糊記憶。
- 來源檔中的純文字先後順序。

每句台詞的說話者判定須標為以下其中一類：

- `Explicit`：同一來源記錄明確具名或有技術性匿名標籤。
- `Corroborated`：來源無名，但有事件結構明證，或至少兩項互相獨立且沒有衝突的其他證據。
- `Anonymous-safe`：無法確定姓名，但能安全確定陣營、兵種、性別、事件身分，或來源本來就刻意保持匿名。
- `Unresolved`：只能靠輪流、語氣或猜測；不得具名，也不得把章節標示為完成。

### 8. 匿名角色與內心獨白

- 匿名來源應使用文本實際能支持的最窄類別，例如「一名魏軍步卒」「一名漢軍將士」「那名女子」或「陣中不知名者」。
- 同一技術性匿名標籤在同一事件內重複出現時，敘事提示必須維持為同一人，不得每次都當成新的「有人」。
- 原文說話者不明時，不得依語氣或對話輪次武斷指定；可用有來源支持的中性敘述明確告知讀者此人身分未明。
- 每句 `（）` 內心獨白都必須綁定一名視角人物或來源所示的匿名人物。
- 不得把數名角色的內心獨白連續排列，只以「眾人各懷心思」或列名順序概括歸屬。
- 不得把無法判定歸屬的內心獨白改寫成說出口的話、群體心聲或旁白。
- 若必要事件中的說話者仍為 `Unresolved`，必須繼續查證或列為阻塞項，不得以模糊提示掩蓋後宣稱驗證通過。

### 9. 說話者提示不得改寫角色

- 新增提示只能位於台詞之外，優先使用「姜維道」「柳隱回答」「諸葛果接過話頭」「廖化心中暗道」等中性敘述。
- `問道` 只用於原句確為提問，`答道` 只用於確為回答。
- `怒喝`、`冷笑`、`譏諷`、`哭喊`、`口吃`、`故作輕佻` 等帶有情緒或習慣的描述，必須有原文、動作或場景證據，不得為避免重複而憑空添加。
- 不得為建立提示而替角色新增口癖、稱呼、自我介紹、慣常動作或任何直接對話。
- 不得先描寫甲的動作或心理，再無提示地接上乙的台詞，使讀者先判給錯人。

## 六、系統文字處理

### 1. 原則上不寫入正文

以下內容通常屬遊戲介面或控制資訊，不是小說對話：

- `戰前處置`
- `戰中處置`
- `戰後處置`
- `玩家切換`
- `友軍控制`
- `HEX我軍設定`
- `個人裝備設定`
- 勝利條件
- 失敗條件
- 印綬條件
- 達成印綬提示
- 選項文字本身

這些內容應轉化為情節、戰況或省略，不可直接當成世界內旁白。

位於冒號前的 `士兵01`、`步兵1`、`女子1` 等發話者標籤不屬於可任意省略的系統文字。雖然編號通常不直接寫入小說，仍必須保留其身分與同一性，供說話者驗證使用。

### 2. 教學型內心獨白仍須保留

若教學內容以角色內心獨白形式出現，且採用的分支會播放該段文字，就仍屬原始角色文本，必須逐字保留。

處理方式：

- 將其安排為角色臨戰前的兵法整理、戰術推演或自我提醒。
- 用戰場動作穿插長篇教學，避免形成純說明書。
- 不可因為內容帶有遊戲術語就擅自刪改。

## 七、小說文體

### 1. 整體調性

採「三國演義骨架，現代輕小說節奏」：

- 旁白有歷史感、戰亂感與章回小說氣勢。
- 句子清楚流暢，不全面仿古，不使用難以閱讀的半文言堆砌。
- 人物互動保持原作直接、鮮明、帶喜劇節奏的特色。
- 戰略、政治與制度辯論要寫得清楚，不能只剩武打場面。
- 悲劇場景要克制，依靠人物選擇和後果形成重量，不濫用哭喊或煽情形容。

### 2. 章回體元素

每章原則上包含：

1. `# 第X回　七字或近似對仗上句　七字或近似對仗下句`
2. 開場短詩，可用兩句或四句。
3. `話說`、`卻說`、`再說` 等章回轉場，但不可每段濫用。
4. 場景內使用 Markdown 二級標題分節。
5. 戰後以短評、對句或詩句收束。
6. 章末使用 `欲知……且看下回分解。`
7. 最後附改寫註記。

回目要概括本章兩個主要事件，不劇透遠期結局，不使用空泛標題如「命運的開始」。

### 3. 輕小說元素

- 對話獨立成段。
- 對話獨立成段不代表可以連續排列成無名台詞清單；風險點仍須依第五節補足說話者錨點。
- 動作與反應簡潔明確，讓角色互動有節奏。
- 可以寫尷尬、吐槽、誤會與反差，但笑點必須來自原角色性格或原始台詞。
- 重要人物登場時，用一至兩段建立外貌、氣質、身分與當下目標，不寫成資料卡。
- 心理描寫貼近當前視角，不長篇重複角色已說出口的內容。
- 每一場景都要有目標、阻力、轉折與退出點。

### 4. 敘事視角

- 以第三人稱全知旁白為主。
- 單一場景內盡量貼近一名核心人物，可在明確分場後切換視角。
- 可以使用章回小說式預示，但只預示原作已確定的後續，不擅自添加新命運。
- 不要在同一段中頻繁跳入多名角色內心。
- 原文已有括號內心獨白時，必須保留，並讓前後敘述支持該視角。

## 八、敘事擴寫規則

### 1. 可以新增

- 天候、地貌、城池、營寨與室內陳設
- 服飾、兵器、軍旗與軍陣的可見細節
- 原文已能推導出的動作、表情與停頓
- 戰術如何落實到地形和兵力的過程
- 戰鬥中的走位、攻防、混亂與撤退
- 必要的史實背景和人物身分介紹
- 場景之間的時間與空間銜接
- 不改變事件結果的群眾反應
- 不改變角色性格、動機與台詞內容的中性說話者提示

### 2. 不可新增

- 改變角色動機的新設定
- 原文不存在的戀愛承諾或親密行為
- 影響後續的傷勢、道具、伏筆或人物關係
- 未經文本支持的陰謀與幕後黑手
- 讓角色提前知道後續真相
- 與選定路線衝突的人物死亡或存活
- 為了場面華麗而改變勝負、時間、地點與參戰者

### 3. 戰鬥描寫

- 先交代地形、雙方目的與戰力差異，再進入交鋒。
- 招式名與單挑台詞必須保留原文。
- 在原台詞之間補上槍路、步法、受力、視線和戰場變化。
- 不把每一擊都寫成毀天滅地；武將強弱要由攻防結果呈現。
- 戰場勝負以 `R_*` 戰後敘述和下一章開頭為準，不能只按玩家可操作的勝利條件判斷。

### 4. 政治與歷史

- 使用角色當時認知的國號與立場。例如魏方稱蜀漢為蜀人或蜀軍時，不擅自改成中立稱呼。
- 同一人物可能有本名、字、官職與敬稱；依原對話和當時關係使用。
- 史實補充必須服務當前場景，不寫成百科全書。
- 本作含大量架空史，進入架空線後不得用真實歷史強行否定文本事件。

## 九、語言與格式

- 全文使用繁體中文。
- 使用全形中文標點。
- Markdown 段落之間空一行。
- 旁白原則上不使用粗體、斜體或大量括號強調。
- 人名、官職、地名與國號採原始文本用字。
- 不自行把 `甯隨` 改為其他異體字。
- 不使用網路流行語、現代品牌或現代制度比喻，除非原始角色台詞本身如此。
- 不使用「鏡頭一轉」「畫面來到」「玩家看到」等影視或遊戲介面語言。
- 不在正文討論來源檔、選項、旗標或改寫工作；這些只放在章末改寫註記。

## 十、檔案命名與章節連續性

- 小說檔案放在 `chapters/` 目錄。
- 沿用 `chapters/novel-chapter-01.md` 格式，後續命名為 `chapters/novel-chapter-02.md`、`chapters/novel-chapter-03.md`。
- 史實線從第三十三回平行分流，檔名使用 `chapters/novel-history-chapter-33.md` 起，正文回號仍沿用「第三十三回」而不接續真結局線編號。
- 檔名使用英文與兩位數章號，正文回目仍使用中文「回」。
- 新章開頭要檢查上一章最後三至五段，保持時間、地點、人物狀態與懸念連續。
- 新章完成後，如發現前章的選項造成連續性錯誤，先報告衝突，再做最小修正；不得默默重寫大量既有內容。

## 十一、標準生成流程

### 步驟 1：盤點來源

讀取候選 `R_*`、`S_*`、前後章開頭與分析文件，確認真正的章節範圍。

### 步驟 2：建立事件順序

列出本章場景、參與者、選項、戰鬥結果和下一章鉤子。先解決重複事件與互斥分支，不能邊寫邊猜。

### 步驟 3：建立台詞暨說話者台帳

以來源檔、offset 與行號記錄本章採用的全部：

- 直接對話
- 內心獨白
- 單挑台詞
- 無名戰中台詞

每筆至少記錄來源 ID、原始說話者標籤、正規化後的說話者、判定類別、證據、逐字台詞、小說對應位置與可見錨點。同時標記不採用分支與系統文字。

### 步驟 4：設計章回結構

先定回目、開場詩、分節、高潮、戰後收束與下回鉤子，再開始正文。

### 步驟 5：在台詞之間擴寫

先按原順序放入所有採用台詞，再補敘事。不得先自由寫完，再憑印象補幾句原文。

放入台詞時先依第五節規劃說話者錨點。新增提示只能放在台詞之外，且不得以情緒、口癖或虛構動作代替可靠歸屬。

### 步驟 6：連續性檢查

核對：

- 人物是否在場
- 傷亡與加入狀態
- 官職與稱謂
- 時間與地點
- 選項結果
- 戰役勝負
- 下一章開頭
- 每句台詞的說話者及當時是否在場
- 多人場景與內心切換是否都有有效錨點
- 匿名標籤是否在同一事件內維持一致

### 步驟 7：逐句驗證

將來源記錄與小說正文進行內容、順序、說話者及讀者可見錨點的雙軸比對。驗證必須涵蓋本章採用的全部台詞，不能只抽查。

驗證報告至少要得到：

```text
Content matched: N/N
Content order: N/N
Extra direct dialogue: 0
Explicit speaker attribution: E/E
Corroborated speaker attribution: C/C
Anonymous-safe attribution: A/A
Reader-visible speaker anchors: K/K
Wrong-speaker assignments: 0
Blocking unresolved speakers: 0
Unselected-branch leakage: 0
```

若有任何缺句、字詞差異、錯置、無提示風險點或未決歸屬，先修正再交付。

### 步驟 8：格式檢查

執行：

```bash
git diff --check -- "chapters/novel-chapter-XX.md"
```

確認 Markdown 無多餘行尾空白、衝突標記或格式錯誤。

### 步驟 9：完成摘要

交付時簡述：

- 新增或更新的檔案
- 本章來源範圍
- 採用路線與選項
- 台詞驗證結果
- 說話者歸屬與可見錨點驗證結果
- 未採用分支

## 十二、台詞驗證準則

驗證時比較的是「來源記錄、說話者與台詞內容」，不是只比較匯出排版：

1. 將來源 `[OFFSET]` 保存為來源記錄 ID，不可直接丟棄。
2. 將來源的 `角色名：` 解析並保存為原始說話者欄位；內容比對時可分離角色名，但歸屬驗證必須保留它。
3. 移除可確定是排版造成的空白與換行。
4. 不執行 Unicode 正規化、異體字轉換、標點轉換或省略號正規化。
5. 小說直接對話只移除小說額外包上的最外層一組 `「」`；原始台詞本身已有的引號必須保留。
6. 內心獨白的 `（）` 屬原文內容，不得移除。
7. 每條已選來源記錄必須依事件順序恰好對應一條小說記錄；重複台詞仍須以來源 ID 分別對齊。
8. 確認正規化後的每句來源台詞完整出現在小說中，且順序與來源事件一致。
9. 反向掃描小說中的直接對話與內心獨白，確認每一條都能回指已選來源，結果必須為 `Extra direct dialogue: 0`。
10. 逐筆核對來源說話者、小說歸屬、角色在場狀態及最近的有效敘事錨點。
11. 對每句執行說話者隔離測試；來源正確但讀者無法由正文辨識時，仍判定為失敗。
12. 另行搜尋未採用分支的代表句，確認沒有誤混入正文。

第一次按來源順序檢查「來源到小說」，第二次按小說順序檢查「小說到來源」。不能只用字數、相似度、單向搜尋、角色口癖或人工印象宣稱「完全保留」或「歸屬正確」。

完成每章前逐項確認：

- [ ] 未混入互斥分支。

- [ ] 來源具名台詞沒有降格成含糊的「有人」，匿名標籤也未被擅自具名。
- [ ] 說話者判定不依賴口癖、語氣、輪替或最近人物猜測。

## 十四、禁止事項

- 禁止修改 `ExtractedScripts/` 原始文本。
- 禁止為了文筆順暢而潤飾角色台詞。
- 禁止把台詞原文逐字保留卻錯置給其他角色。
- 禁止只靠口癖、語氣、一人一句輪替、最近人物或既有小說安排判定說話者。
- 禁止在來源已具名時只寫成「有人」，或將匿名人物無證據改成具名角色。
- 禁止連列多人內心獨白，只用「眾人各有所思」或列名順序要求讀者自行分配。
- 禁止先聚焦甲的動作或心理，再無提示接上乙的台詞。
- 禁止只以 `Matched N/N` 或內容搜尋結果宣稱說話者歸屬正確。
- 禁止把遊戲選項全部串成同一段劇情。
- 禁止跳過來源盤點，直接依分析摘要寫作。
- 禁止把推測的好感值、旗標或跳轉當成既定設定。
- 禁止任意刪除不合現代口味的粗口、政治觀點或角色缺點。
- 禁止用作者說教取代原作的政治辯論。
- 禁止讓旁白提前裁定角色善惡；應由行動、台詞與後果呈現。
- 禁止只寫事件摘要而缺乏場景、動作與情緒進程。
- 禁止只追求篇幅，重複解釋同一資訊或堆疊空泛形容。
